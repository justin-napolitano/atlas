# Publication trust boundaries and release review

Scope: private PostgreSQL authoring → sole-owner preview/approval API → approved public snapshots/heads → future isolated builder → immutable anonymous site. Personal notes, source excerpts, identities, and editorial rationale are private. Published text is intentionally public but still subject to attribution/rights and scholarly limitations. The builder/deployment boundaries remain unimplemented. This is an implementation threat record, not a completed independent security review.

| Threat | Initial impact | Current control and verification | Remaining gate |
| --- | --- | --- | --- |
| Spoofed owner/agent approval | High: unauthorized disclosure or false attribution | Signed IAP subject boundary and write/origin checks; actor derived server-side; publisher cannot execute approval functions; HTTP and SQL negative tests | Live IAP setup, no worker SQL authority, scoped proposal identities |
| Hidden private state copied to publication | High: notes, reading history, or licensed text disclosed | Fixed projector; summaries/bibliography opt in; private reading tables never inputs; nested SQL shape checks; synthetic private-marker tests | Human payload/rights review, publisher image contents and every derived public search/path/ranking/export checked |
| Preview changes between inspection and approval | High: publish unseen text | Sealed previews, digest comparison, selected-input locks, source-state equality, expected head revision; stale/competing approval tests | Live concurrent workload and operational capacity checks |
| Runtime escalates into public tables/history | High: bypass approval/audit | Separate schemas/logins, column grants, exact function registry, fixed search paths, revoked PUBLIC execution; direct SQL negative tests | Independent security-sensitive function/role review and real Cloud SQL IAM topology |
| Private rationale/actor leaks through provenance | High: identity/research privacy loss | Events and raw inputs private; publication returns only head metadata and allowlisted graph; relation provenance internals omitted | Future provenance/export expansions must preserve this boundary |
| Approval misrepresented as verified scholarship | High: public conclusions overstate evidence | Original review state retained; publication policy disclaimer; imported review scope retained without promotion; canonical pilot test | Actual editorial review workflow and manually rechecked pilot article |
| Withdrawal or rollback republishes stale content | High: withdrawn/private text remains accessible | Active-head-only transitional public reads; immutable historical retention; withdrawn approval retry rejected | Replacement immutable image, cache policy, withdrawal-aware rollback and live drill |
| Denial of service or storage growth | Medium: costly previews or unavailable authoring | Request-size/rate/time limits; selections/payload bounded; SQL timeouts; no local daemon added | Preview retention, job quotas, connection budgets, measured costs/capacity |
| Lost response or concurrent click creates duplicate release | Medium: inconsistent public head or audit | Atomic approval/head/event; same current successful retry idempotent; head compare-and-swap; race tests | Resumable publisher build/deploy and last-good release verification |

No billable resources are provisioned, no OAuth/IAM deployment verified, and no exception or production approval is asserted. Review this boundary before public exposure; complete hosted restore, rollback, and withdrawal gates under #31/#41/#42.
