# Private reading excerpts and passage capture

The owner API and reading workspace can import a plain-text excerpt, select an exact passage, and retain a private annotation with a stable target. This is reading application state: it neither changes canonical curated RDF nor publishes imported text or scholarly claims. HTML extraction, arbitrary third-party page annotation, and full-document/PDF reading remain follow-up work in #43.

## Reader flow

Open a source in the owner workspace, expand **Add text to read here**, and supply edition/version, location, optional original URL, and a short plain-text excerpt. Saved versions remain separately selectable. Select a word or passage, choose **Annotate selected text**, then add a private note or label it as a term/reference candidate. Saving attaches it to that immutable version. **Saved passage notes** reopen and highlight the exact stored range; an export button downloads its private Web Annotation JSON-LD. A late response from another selected version cannot highlight the new version.

DOM selection ranges convert UTF-16 offsets into Unicode code points; where available, Intl.Segmenter rejects partial grapheme boundaries, including emoji/Arabic marks. Source text and comments render as escaped text, never executable imported HTML. The original source link remains available when no excerpt is imported. This is not a browser extension for annotating external sites.

Unsaved excerpt/capture drafts stay in page memory when switching records and trigger a reload warning; they are not saved offline. Import/capture buttons report saved only after owner API acknowledgement. A repeated capture uses its original UUID. Refreshing the saved list helps reconcile a lost response; conflicting versions retain the draft. No browser deletion or automatic graph promotion is included.

Choose **Edit note** under a saved passage to expand its private comment editor. **Save changes** (or Command/Control+Enter) sends the last confirmed revision; typing while a save is pending leaves the newer text unsaved until another explicit save. Returning to the source preserves the editor draft and its reading version in page memory. Reloading retains acknowledged cloud saves; unsaved text has a browser leave warning and must be saved or copied before closing the page. Private comments are not stored in localStorage.

If another machine edited the comment, the editor retains your draft beside the current cloud note. **Use cloud note** accepts that version; **Save my version** attempts a new revision against the displayed cloud version and may conflict again if it changed. No automatic overwrite or text merge occurs. A retry after a lost successful response can recognize matching saved content without duplicating the revision. **Discard my changes** explicitly drops the unsaved edit. Editing changes only the comment body; target selection, capture kind, source version, and history stay attached. The export button fetches the saved server annotation, not an unsaved draft.

The compiled browser check verifies selection on text containing emoji, persistence/reopening, new and existing note draft retention across navigation, an actual UI conflict comparison/resolution, and reload of the edited note using synthetic responses. Controller tests cover pending-save typing, stale refreshes, response identity, network failure, and lost-response retries. PostgreSQL tests separately verify the actual durable API and anchor constraints. Hosted IAP routing and cross-device deployment remain prerequisites.

`POST /v1/reading/documents` requires a project/source ID, owner-declared edition/version, domain locator, optional HTTP(S) representation URL, and 1–12,000 characters of supplied plain text. The source must be an active source/work/edition in that project. There is no URL fetch or embedded HTML execution. The existing 64 KiB request limit also applies. Only line endings normalize to LF; characters, diacritics, and other whitespace are retained. Both input and normalized text hashes are recorded, along with actor/time and explicit unverified-source review scope. These are excerpt hashes, not claims to have checksummed a full published edition.

Snapshots are immutable. An identical import reuses its identity; a new text/edition/location produces a new snapshot. Bounded metadata listings omit the text body. Full text requires a separate authenticated document request. All new tables and revision history are private, with PUBLIC grants revoked; public mode registers none of the reading routes.

`POST /v1/reading/annotations` accepts a client-generated UUIDv4 (reuse it for retries), snapshot ID/hash, start/end, exact selection, capture kind, and private Markdown comment. Start is inclusive and end exclusive. Positions count Unicode code points in logical order. The selected span is 1–500 characters; prefix/suffix retain up to 40 surrounding code points. Source hash and selected text must match the immutable snapshot. Common combining-mark/ZWJ/skin-tone boundaries are rejected; this guard is not a complete implementation of every extended grapheme rule. A browser client should use a grapheme-aware selection boundary as well as converting UTF-16 DOM offsets.

Capture kinds are comment, term candidate, and citation candidate. All remain `captured_unreviewed`. Exact anchoring proves only which stored text was selected, not correct attribution, OCR, translation, a definition, a scripture resolution, or scholarly agreement. Duplicate capture retries do not create extra revisions. A different payload under an existing capture ID conflicts. Annotation bodies update with expected revisions and retain immutable history; targets cannot be rewritten in place.

The [W3C Web Annotation model](https://www.w3.org/TR/annotation-model/) supplies quote and position selectors. `GET /v1/reading/annotation` returns the captured row, anchor diagnostic, and a JSON-LD annotation with the snapshot ID and edition/locator/hash context. Export includes the selected span and private comment, never automatically the complete document. It is a private export, not a publication action. Remote JSON-LD contexts are not fetched by this implementation.

Changed text returns a changed-source diagnostic, with ambiguous/missing candidate information where applicable. A unique textual match still requires review and does not relocate itself. Invalid selectors in an unchanged version fail anchoring. Updating extraction or OCR therefore needs a new snapshot and explicit re-selection; historical targets remain stable.

Tests cover Unicode/emoji/Arabic positions, combining sequences, input normalization, tampering, source drift, ambiguity/orphans, bounded exports, idempotent imports/captures, immutable versions, project isolation, revision conflicts/history, private grants, and signed-owner HTTP round trips. No source was newly read or scholarly-review state promoted by these implementation tests.
