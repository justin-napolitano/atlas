# Located passage → verse connections

`web/src/VerseLinks.jsx` is an owner-only saved-passage widget for the verse-material API delivered in #106. It is separate from automatic reference detection and the resolution of explicit citation markers. No verse, interpretation, or graph edge is attached merely because a word appears in a source.

Expand **Link to verse**, inspect existing connections, then choose a surah/ayah range. The first UI supports scholarly discussion or attributed interpretation, with source roles scholarship, tafsīr/commentary, or linguistic annotation. Attribution, scope/limits, the reason for the connection, and explicit confirmation are required. A quotation must equal the whole immutable source selection; a paraphrase is explicitly labeled. Neither mode establishes that the interpretation is correct or represents all Muslim traditions. New connections remain private and pending scholarly review.

The standalone component takes `api`, `projectId`, `annotation`, optional `sourceTitle`, the shared `drafts` ref, `changed`, and `onOpenVerse(reference)`. `annotation` must include `id`, `project_id`, `document_id`, `text_sha256`, and `exact`. The callback receives the server's stable reference object, including `id`, `label`, `chapter`, `ayah_start`, and `ayah_end`. The containing reader supplies navigation and its existing unload warning. This component introduces no authenticated application entry or authentication bypass.

The initial render performs no fetch or write. Expansion/refresh reads `GET /v1/verses/annotation-links`; additional pages are explicit. Saving uses `POST /v1/verses/materials` with `citation_basis: none`, then verifies `GET /v1/verses/material` against the project, annotation, document hash, exact selected wording, target range, material/link type, attribution, scope, rationale, and asserted wording. Explicit-citation claims, translation/text imports, historical metadata editing, existing connection correction/withdrawal, and public projection remain outside this first widget.

Drafts are project-and-annotation scoped in page memory. Unknown write outcomes retain the exact payload and UUID; inputs lock until the identical request is acknowledged. An initial known validation rejection permits correction, while a rejection after uncertainty keeps the original request. A mismatched successful response cannot clear a draft or create a navigation link. A private JSON draft download supports manual recovery; it is not an automatic import/sync format. Unsaved text does not survive closing the tab unless downloaded; saved connections require the authenticated database-backed application to reopen across devices.

Verification: `npm test` includes source identity, Unicode/Arabic quotation, scope/confirmation, wrong-project readback, and retry tests. `node scripts/review-verse-links.mjs` in `web` compiles the real component into an isolated harness and exercises an explicit synthetic API adapter: committed-but-lost retry, exact retained payload across remount, no duplicate connection, discussion/quotation distinction, source-bound readback, paginated connections, verse callback, incorrect-project refusal, 390px overflow, and absence of private localStorage. This is frontend evidence, not proof of live authentication or hosted persistence; #106 supplies the separately verified PostgreSQL/API contract.
