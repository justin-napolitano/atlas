# Owner research search

`GET /v1/search?project_id=…&q=…` searches live record titles and summaries in the selected project. Add `scope=notes` for private record notes, `scope=annotations` for selected passage text/private passage comments, or `scope=all` for all three. Optional `kind` filters the parent record type; `limit` is 1–100 (default 30). The default never searches private note channels. All search routes require the verified owner; the public service has no corresponding route.

The implementation uses PostgreSQL's `simple` text configuration and parameterized `plainto_tsquery`. All tokenized terms must match in a record or note channel; terms do not distribute across channels. Input is never SQL or raw tsquery syntax. Case normalization and Unicode tokenization are available; synonym expansion, embeddings, Arabic morphology, transliteration equivalence, and author-name disambiguation are not. The query `tafsir` does not imply `tafsīr` or `التفسير`. Punctuation-only input returns no matches; empty/whitespace queries are invalid.

Results have one row per parent research record, with each matched channel's excerpt, lexical score, and revision. Annotation matches also carry the exact annotation/document IDs, capture kind, and captured-unreviewed status. They search the selected text and comment; the unselected full reading excerpt is not searched or returned. Record title/summary ranking uses PostgreSQL weights A=1.0/B=0.4; notes and annotations use D=0.1. Cover-density scores normalize with option 32 (`rank / (rank + 1)`), then combine using the maximum channel score. These are lexical retrieval signals, not probabilities, academic quality, or the separate ranking profiles. Ties use stable IDs. `truncated` identifies bounded top records; no exhaustive pagination is provided.

Each record returns at most five matches per channel, ordered by score and target ID; `matches_truncated` reports omitted matches. Returned record summaries stop at 2,000 characters with a `summary_truncated` flag; full records remain available via `/v1/record`. A private annotation index uses the same live revision authority as editing. Source/project/type/tombstone filtering precedes results. Public views and counts do not acquire these private matches.

The workspace provides individual **Open exact passage** links. URLs retain project, source-record, and annotation IDs, so reopening or reloading selects the annotation's immutable document version and checks its anchor. A mismatched source/annotation link does not display the other source's passage under the wrong record. New tabs still require owner authentication. Existing drafts remain in page memory when following these links within the app.

Every channel filters project, record type, and tombstones before ranking. Notes search uses the same live PostgreSQL state and revision authority as note editing, so it needs no asynchronous external index. Notes have a dedicated private GIN index. Neither query text nor excerpts are added to structured API logs. Returned excerpts are **untrusted plain text**; clients must render them as text, never inject them as HTML. The response explicitly states retrieval method, weights, and limitations.

An owner-authorized agent client can use this endpoint to retrieve matching source/note IDs, fetch the current full record via `/v1/record`, and follow registered evidence paths. An agent must obtain a supported signed owner identity through the deployed authentication path; this change does not create agent credentials, grant anonymous access, or implement an MCP transport. No write, review, or publication decision follows from a search result.

Tests use real PostgreSQL for private-note scope, channel/revision provenance, project isolation, type filters, ties/limits, Unicode, literal query handling, immediate note updates, and tombstones. HTTP tests cover sign-in requirements, default scope, input limits, and missing public routes.
